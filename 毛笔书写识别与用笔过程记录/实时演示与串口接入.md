# 实时书写窗口：演示与 USB 串口接入

版本：v0.2，2026-11-08。波特率已确认 115200；真实串口行格式待硬件组提供。

## 1. 现在怎样看见写字的过程

启动工作台后打开 http://127.0.0.1:8765/ ，顶部就是实时窗口。

1. 点击“试播模拟实时流”，检查软件链路。合成信号会持续约 6 秒，样本数、六轴数字、笔杆姿态与曲线持续变化。
2. 点击“演示大屏”，隐藏左侧导入区，投影时更集中。模拟源始终标为“非真实书写”。
3. 流结束后自动检查采样质量、匹配模板并显示报告；时间线切换为回放。
4. 点击“开始真实记录”不会伪造设备数据。没运行串口桥/HTTP 发送端时，它会显示“等待设备数据”，数值保持空白。
5. 真实写完一个字后点“结束并分析”。只有已经到达 Python 的样本属于本次报告；本版还没有固件侧结束确认协议。

流程是：开始记录 → 等样本数增长 → 写完整一个字 → 笔停稳、确认数据更新 → 结束并分析 → 回放或提问。

实时可以展示运动过程；单字类别在书写结束后判断。参考字形不会随着笔画生成墨迹。只靠六轴 IMU，当前不宣称还原实际纸面字形、压力或精确笔尖位置。

## 2. 真实硬件链路

    MPU6050 → ESP32-S3（采样/姿态/距离算法）
            → USB 串口 115200
            → serial_bridge.py（解析、批量上传）
            → Python 保存样本
            → 网页每约 100 ms 增量取新样本

每次采样仍应保留设备时间戳和序号。推荐 100 Hz；网页约 10 次/秒刷新，通常每次处理多个新样本。串口桥约 80 ms 一批，实际延迟需要真实设备联调测量，不能从两个时钟直接相减推算。

已确认的参数只有 115200。以下是适配器支持的格式示例，不是对当前固件格式的断言。

逐行 JSON（每个样本一行，以换行结束）：

    {"sample_us":1000000,"seq":1,"boot_id":"boot1","ax_g":0.01,"ay_g":0.02,"az_g":1.0,"gx_dps":1.0,"gy_dps":2.0,"gz_dps":3.0,"roll_deg":0,"pitch_deg":-30,"yaw_deg":0}

CSV（先一行表头，再逐样本一行）：

    sample_us,seq,ax_g,ay_g,az_g,gx_dps,gy_dps,gz_dps,roll_deg,pitch_deg,yaw_deg
    1000000,1,0.01,0.02,1,1,2,3,0,-30,0

必需字段和单位见硬件数据接口约定。调试文字建议加 # 前缀独立成行；非法行会计数告警，不会补成假样本。若设备输出二进制帧，需要收到协议后新增解析器，不直接选择 JSON/CSV。

## 3. 串口桥命令

在项目目录使用同一个 Python 环境（第一次需要安装 pyserial）：

    D:/conda3_envs/zzss/python.exe -m pip install -r requirements-hardware.txt
    D:/conda3_envs/zzss/python.exe serial_bridge.py --list

确认端口后运行（COM5 只是示例，换成实际端口）：

    D:/conda3_envs/zzss/python.exe serial_bridge.py --port COM5 --baud 115200 --format jsonl

若硬件输出带表头 CSV：

    D:/conda3_envs/zzss/python.exe serial_bridge.py --port COM5 --baud 115200 --format csv

无表头 CSV 须显式指定 --columns，顺序必须与固件一致，不要猜测轴和单位。串口桥会先观察表头，网页开始记录后清除设备的旧串口缓存，只转发新采样。串口不能同时被串口监视器等另一程序占用。

如配置了 API 令牌，启动串口桥的进程也需设置环境变量 BRUSH_API_TOKEN。脚本不经过 Windows 系统代理连接本机服务。

## 4. 开始、断线与结束

- 同时只允许一条实时会话。刷新页面会发现进行中的会话，并从游标 0 补齐已保存样本。
- 浏览器短暂断开时，串口桥仍可上传；页面恢复后补取已保存数据。
- 页面显示“数据暂未更新”仅意味着没看到新样本，不直接证明物理设备断电。
- HTTP 提交超时且不确定是否落盘时，桥会停止，不盲目重发造成重复；请结束本段、检查后重新采集。本版没有可靠传输 ACK/批次幂等协议。
- 点击结束的边界以服务器已接收的样本为准。结束后在途/待发送样本不再追加；写完后停稳并等最新数字更新再结束。后续若需严格逐样本收尾，应让固件返回最终 seq 和完成确认。
- 页面恢复只是补取，不会把没采到/没传到 Python 的数据“恢复出来”。

## 5. 路演话术和验证范围

硬件真正联通后，可以现场展示“手上的笔在动，网页上的姿态和曲线同步变化，写完能复盘”。演示前固定安装，准备个人模板和独立验证记录。模板不足时系统会如实显示“待建模板”。

软件测试覆盖游标、批量保存、会话恢复、模拟取消和鉴权；真实硬件格式、端口、延迟和识别效果待实测。电脑操作工具未能可靠确认浏览器地址，因此本次未完成浏览器交互验收；交付后仍需在实际浏览器点击模拟流检查布局和回放。
