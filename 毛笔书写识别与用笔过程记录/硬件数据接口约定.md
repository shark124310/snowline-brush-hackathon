# 毛笔 IMU → Python：硬件数据接口约定 v1

先按一个完整字导出 CSV，每行是一个采样点，建议 100 Hz。电脑端不依赖硬件距离算法完成。

## 1. 列名和单位

| 列名 | 单位 | 约定 |
|---|---|---|
| sample_us | 微秒整数 | 必需；设备时间严格递增，建议 64 位 |
| ax_g, ay_g, az_g | g | 必需；含重力，说明是否做比例修正 |
| gx_dps, gy_dps, gz_dps | °/s | 必需；说明是否扣零偏 |
| seq | 整数 | 建议；每次采样递增，包序号另用 packet_seq |
| boot_id | 整数或文字 | 建议；设备重启后变化 |
| roll_deg, pitch_deg, yaw_deg | 度 | 可选；约定设备轴和旋转顺序 |
| distance_mm | mm | 可选；硬件算法估计值，不宣称真实笔尖位置 |
| distance_quality | 文字 | 可选；距离估计状态 |
| clipped | 0/1 | 可选；达到量程限制时为 1 |
| rest, accel_used | 状态 | 可选，保留固件标记 |
| firmware_version, filter_version | 文字 | 可选；版本信息 |

其他平面标量列保留。x_mm/y_mm/z_mm 等位置估计可以传入，本版不把它们绘制成真实笔尖轨迹。若硬件输出米或厘米，要先确认转换，不能只改列名。

字段示意（只有两行，不足以识别）：

    sample_us,seq,boot_id,ax_g,ay_g,az_g,gx_dps,gy_dps,gz_dps,roll_deg,pitch_deg,yaw_deg,distance_mm
    1000000,1,boot1,0.01,0.02,1.00,0.1,0.2,0.3,0,-30,0,0
    1010000,2,boot1,0.02,0.01,1.00,0.2,0.1,0.4,0.1,-30,0,0.2

## 2. 质量规则

- CSV 最多 5 MB、20,000 个样本；必须有上述七个必要字段和有限数值。
- 低质量记录可以保存回放；模板/单字识别要求时长 0.5～15 秒、有效保存频率至少 45 Hz。
- 时间重复/倒序、超过 100 ms 的设备时间缺口、采样序号不连续、混合 boot_id 或 clipped 标记均禁止模板和识别。
- 缺少完整 seq 时给出警告，不能宣称已经验证无漏采样。
- 不重复做未知的零偏补偿，不用设备时间减电脑 Unix 时间计算单向延迟。
- 30 秒流可以检查采样；请另外导出逐字片段。长流仍保存，但会提示不适合单字识别。

## 3. 导入接口

POST /api/v1/brush/records/import，采用 multipart/form-data：

| 参数 | 含义 |
|---|---|
| file | CSV 文件 |
| writer_id | 例如 writer-01 |
| mount_id | 例如 mount-01，固定安装版本 |
| mode | practice / template / validation / test |
| label | 模板、验证、测试标注；练习留空 |
| title | 可选，记录标题 |

Python 上报示例：

    import requests
    with open("一次书写.csv", "rb") as f:
        result = requests.post(
            "http://127.0.0.1:8765/api/v1/brush/records/import",
            files={"file": ("一次书写.csv", f, "text/csv")},
            data={"writer_id": "writer-01", "mount_id": "mount-01", "mode": "practice"},
            timeout=30,
        )
    print(result.json())

响应采用 code/msg/data；成功 code=0。格式、状态冲突和鉴权错误使用真实 HTTP 状态码。完整模型见 /docs。

## 4. 实时 HTTP（已实现，待固件联调）

网页“开始真实记录”调用 POST /api/v1/brush/live/start，串口桥或硬件可以通过 GET /api/v1/brush/live/current 获取正在录制的记录 ID（status=recording、source_kind=real）。一次只允许一条活动实时会话。网页重新打开可以恢复它，结束前不要切换记录 ID。

1. POST /api/v1/brush/records：JSON 元数据，返回记录 ID。
2. POST /api/v1/brush/records/{id}/samples：JSON {"samples": [...]}，每次 1～1,000 个样本。
3. POST /api/v1/brush/records/{id}/stop：结束记录；重复调用不重复写数据。
4. 再调用 /recognize、/report、/samples 识别或查看。

不要把接收、模型或页面刷新放进 ESP32 采样时序。传输可以批量，服务器会保留每个样本及其时间。

v0.2 已有实时窗口：GET /api/v1/brush/records/{id}/feed?after=0&limit=1000 按游标增量拉取，每次用返回的 next_cursor 继续。网页约每 100 ms 请求一次，设备仍建议 100 Hz 保存；页面刷新不决定采样频率。游标是样本数量，不是 seq。最后一批追齐且 status=completed 后，界面才切回报告。

USB 波特率已确认 115200；请提供一行实际数据及字段单位。serial_bridge.py 预留逐行 JSON 或 CSV，不假设固件已经采用其中某一种格式。详见 [实时演示与串口接入](./实时演示与串口接入.md)。HTTP 与串口代码已就绪，不代表真实固件已经联通。
