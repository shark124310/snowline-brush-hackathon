# 毛笔书写识别与用笔过程记录：MVP 执行计划

> 更新日期：2026-11-08（Asia/Shanghai）
>
> 当前方向：在真实纸面上用毛笔书写，MPU6050 固定在笔杆上；首版不使用纸面摄像头。
>
> 已确认硬件：MPU6050 ×1、ESP32-S3 ×1、0.96 寸 OLED ×1，无磁力计。用户反馈硬件已完成并能联通。
>
> 文档状态：执行计划。识别算法、接口、测试结果与路演闭环尚未实现、验收；文中的数字是拟定目标或已注明来源的历史观测。

## 1. 这一版要交付什么

做一个能真实演示的闭环：

```text
笔杆装 IMU → 网页开始记录 → 在纸上写一个字 → 结束记录
→ 在“一、十、口”三个候选字中识别，或返回“不确定”
→ 展示书写时长、笔杆姿态变化、角速度与参考记录差异
→ 回放传感器曲线与三维笔杆 → 围绕本次记录与 AI 对话
```

优先验证两个问题：

1. 同一位书写者、固定安装与握笔方式下，六轴运动数据能否区分这三个字？
2. 实际体验者能否看懂记录、识别结果和回放，并完成一次新的书写？

“一、十、口”为首轮候选，分别包含不同的运动过程。是否全部保留，由独立测试决定，不预先承诺识别效果。第一版支持逐字录制，不扩展到整句连续识别。

## 2. 产品能力与展示边界

| 项目 | 首版处理方式 |
|---|---|
| 字的识别 | 根据笔杆运动，在预设小词表内分类；低匹配度时返回“不确定” |
| 纸上的实际墨迹 | 当前没有观测来源；界面不能把参考字形标成实际墨迹 |
| 三维展示 | 显示笔杆朝向和姿态变化；先确认设备轴与笔杆轴的安装关系 |
| 书写轨迹 | 首版不从加速度积分生成真实笔尖空间轨迹 |
| 落笔、提笔及笔画数 | 单 IMU 无法直接测量纸面接触；首版按一个完整字手动分段 |
| 压力、笔锋、墨色 | 当前硬件没有相应观测来源 |
| 反馈 | 书写时长、姿态变化、角速度、与同一人示范的运动差异 |
| 字形、书法水平评分 | 暂无视觉或专家评分依据；不输出专业等级、美观分、压力分 |

首轮定位为“少量字的书写动作识别与用笔过程记录”。DTW 距离是运动序列的差异度，不能称作汉字正确率、书法质量分或识别概率。

## 3. 现状、依据与第一个阻塞点

| 项目 | 当前依据 | 接下来要确认 |
|---|---|---|
| 硬件联通 | 用户已确认 | 实际传输方式、数据读取和保存代码 |
| 姿态算法 | 既有 README 整合了用户自写六轴滤波方案 | 实际固件版本、字段是否经过补偿 |
| 已有导出记录 | `20261107-112505_摇摆测试1_07dcfc2a.csv` | 导出是否保留全部采样 |
| 毛笔训练样本 | 尚未收到 | 固定安装后重新采集 |
| 可直接使用的中文毛笔权重 | 尚未核验到适配本设备的权重 | 首版采用自采模板＋多轴 DTW |

历史 CSV 观测：40 行、设备时间跨度 13.313918 秒，平均保存频率约 2.93 Hz，最大相邻设备时间间隔约 1.10 秒。这个结果描述的是该次导出，不证明固件内部也只按 2.93 Hz 采样，不能直接据此计算丢包率。

**第一道验收门：确认采样、发送、接收、保存的样本数量，完成一次完整高频记录。** 未通过前，先保留真实数据的预览和保存功能，不依据稀疏数据得出汉字识别效果。

## 4. 硬件安装与标定

1. 在笔杆上固定 IMU，记录朝向、安装位置和安装照片/文字说明；夹具不得滑动。
2. 优先让较轻的 IMU 位于笔杆，ESP32-S3、OLED 留在桌面，通过合适的软线连接；按现有硬件条件实施，先确认不会明显牵扯握笔。
3. 固定纸面、座位、惯用手和起始握笔姿态；纸上划定大致相同的书写区域。
4. 按已有固件流程完成静止零偏标定。先确认导出的陀螺仪是否已补偿，避免电脑端重复扣除零偏。
5. 每次开始练习可记录起始姿态，三维展示使用相对朝向；无磁力计的 yaw 不作为绝对方位。
6. 拆装、转动传感器或明显改变握笔方式后，新建 `mount_id` 并重新验证。模板默认按书写者与安装版本管理。

## 5. 采集与保存规范

### 5.1 频率与时间

- 设备端目标：100 Hz 读取六轴数据，每个采样点保存设备时间戳与采样序号。
- 原始文件：完整保存收到的每个样本，不能由网页刷新计时器定期截取最新值。
- 识别端：质量检查后统一预处理为 50 Hz；从较高频率降采样时先进行相应低通处理。
- 网页：按约 20～30 Hz 刷新即可，曲线显示可以降采样，但不影响原始文件。
- 传输沿用已联通链路；可以批量发送，一个包里保留多个样本的各自时间戳。
- `seq` 在每次采样时递增。若还要统计包序号，另设 `packet_seq`，不要混用。
- 时间与识别主要使用设备时间。设备微秒与电脑 Unix 时间未同步前，不能直接相减作为单向延迟。

### 5.2 数据字段

沿用已存在的字段名，先明确语义，再决定新增字段。以下为拟定契约：

| 字段 | 类型/单位 | 含义 |
|---|---|---|
| `boot_id` | 字符串或整数 | 区分设备重启，重启后不能直接接续上一条记录 |
| `seq` | 整数 | 每个采样点的序号 |
| `sample_us` | 微秒整数 | 设备采样时间，优先使用 64 位计时 |
| `received_at_unix_s` | 秒 | 电脑接收时间，用于辅助检查到达情况 |
| `ax_g, ay_g, az_g` | g | 加速度；明确包含重力及是否完成比例校正 |
| `gx_dps, gy_dps, gz_dps` | 度/秒 | 角速度；明确是否已完成零偏补偿 |
| `roll_deg, pitch_deg, yaw_deg` | 度，可选 | 已有算法输出，用于展示；首版 DTW 不依赖这些字段 |
| `qw, qx, qy, qz` | 可选 | 固件已有时可用于三维展示，记录顺序与坐标约定 |
| `rest, accel_used, clipped` | 可选 | 保留已有状态标记，并确认各标记含义 |

每条字记录另存元数据：`record_id`、`writer_id`、`mount_id`、`mode`、`label`、`schema_version`、`firmware_version`、补偿/标定版本、起止时间、采样目标、数据质量结论。

`label` 用于建模板和评估。识别接口计算时不读取本次待识别记录的标签或练习目标字。

### 5.3 采样验收目标

先录制一段约 30 秒的数据，确认以下目标；均为待实测的工程标准：

- 样本量与设备时间跨度对应的有效保存频率接近 100 Hz，初步允许 90～110 Hz；同样打印固件实际采样计数，辅助区分计时抖动与漏存。
- 设备时间单调；同一 `boot_id` 内 `seq` 无重复、无倒序，并统计缺号。
- 检查设备采样间隔，报告中位数、P95、最大值和超过 100 ms 的缺口数量。
- 同时核对发送、接收和落盘样本数；即使接收间隔有批量抖动，也要保留每个原始采样。
- 断连、设备重启、时间倒序或超过 100 ms 的设备时间缺口，首版将该字标为质量未通过，保留原始记录供排查，不参与模板和识别。
- 先判断设备采样时间，再判断数据到达时间；两者不能混淆。

## 6. 样本采集计划

### 6.1 第一轮：同一书写者的受控识别

固定同一人、同一笔、同一安装和同类纸面，先做以下记录：

| 用途 | 每个字数量 | 三个字合计 | 使用方式 |
|---|---:|---:|---|
| 模板集 | 10 条 | 30 条 | 预处理统计量和参考模板 |
| 验证集 | 5 条 | 15 条 | 选择参数、类别阈值与拒识条件 |
| 独立测试集 | 10 条 | 30 条 | 参数固定后只评估 |

再采集验证用负样本和测试用负样本各约 10 条，例如拿笔静止、非书写挥动、写一个词表外的字。负样本用于检查误触发与拒识；这些少量样本不能代表所有未知动作。

实际操作：

1. 选定采集用途，建立 `writer_id` 和 `mount_id`。
2. 建模板时选择标签，点击开始；写一个完整字，再点击结束。
3. 保存后显示采样质量，低质量样本说明原因并重新采集。
4. 按随机顺序混合写三个字，避免先连续写完一个字再换另一个字带来的时间或安装偏差。
5. 测试记录不用于选模板、拟合归一化统计量或调整阈值。若用测试结果改了参数，就另录新的最终测试集。

首版通过网页手动分段，不依赖自动落笔/提笔检测。建议设置约 0.5～15 秒的单字录制范围，最终根据样本调整并版本化。

### 6.2 第二轮：跨人试用

第一轮通过后再邀请其他人试用。分别报告“使用本人模板”和“使用他人模板”的效果。未经独立跨人测试，路演只描述受控条件下的结果；可以让体验者先建立自己的少量模板。

## 7. 识别算法计划

### 7.1 主方案：多轴 DTW

使用 `tslearn.metrics.dtw_path` 等成熟实现。输入是一段 `[时间点数, 6]` 数组，通道顺序固定为：

```text
ax_g, ay_g, az_g, gx_dps, gy_dps, gz_dps
```

流程：

1. 校验记录质量、单位、标定版本和安装版本。
2. 按设备时间对连续数据处理，不跨重启或长缺口拼接。
3. 应用统一低通与重采样；原始文件保持不变，处理结果单独存储。
4. 仅用模板集拟合每个通道的均值、标准差，统一应用到模板、验证、测试和现场记录；标准差设置数值下限，防止小噪声被无限放大。
5. 初版不对每条记录单独做单位方差归一化，也不通过加速度积分求位置。
6. 计算与每条有效模板的多维 DTW 距离。
7. 按匹配路径长度归一化距离；若库返回 `sqrt(局部平方代价之和)`，可用 `distance / sqrt(path_length)`，并将定义写入算法版本。
8. 每个字取距离最小的 3 条模板的平均值作为类别距离，选择距离最小的类别；模板数量不足 3 条时禁止启用该类别。
9. 对最佳距离和与第二名的差距做验证。阈值由验证集确定，超出阈值或两类过近时返回“不确定”。

DTW 允许速度差异，但不能保证对任意书写者、握笔方式和安装方向都适用。先验证识别，再决定是否增加相对姿态特征、调整通道权重或引入神经网络。

### 7.2 Baseline 与评估

先实现一个简单基线：六轴的均值、标准差、RMS、变化范围等特征＋最近类别中心；若样本和依赖条件允许，再比较逻辑回归。全部使用相同的数据划分。

DTW 报告至少包含：

- 已知三类的整体准确率、Macro-F1、各类召回率、混淆矩阵。
- 已知字被拒识的数量，计入整体识别失败，不通过只统计“有输出”的记录来提高准确率。
- 单独报告负样本拒识率和被错误接纳的类别。
- 从结束录制到返回识别的耗时，报告中位数与 P95；采集时长与推理耗时分开。
- 书写者数量、模板数、验证数、测试数、安装条件和算法版本。

首轮演示目标：独立测试 30 条已知字，至少 24 条识别正确（≥80%），每个字至少 7/10 正确；另 10 条独立负样本至少 8 条拒识。识别返回时间 P95 先以不超过 1 秒为目标，超过时检查序列长度、约束窗口和模板数量。这些是决策目标，不能写成已实现效果，也不代表大规模或跨人性能。

若效果不达标：先排查采样与安装，再调整模板与预处理；仍不达标时缩小到两个实际能区分的字，或明确改为“指定字的示范对照练习”。对照练习界面显示目标字，不伪装成自动识别。

## 8. 软件架构与待建模块

### 8.1 运行位置

| 部分 | 语言/技术 | 责任 |
|---|---|---|
| ESP32-S3 | 继续使用现有 C/C++ 固件 | 采样、已有姿态融合、序号/时间戳、传输、OLED 状态 |
| 电脑端 | Python | 接收、原始保存、质量检查、预处理、DTW、报告 |

| 页面 | 轻量 Web 页面，复用已具备的前端技术 | 开始/结束、曲线、三维笔杆、候选字、报告 |
| AI | 复用已经能调用的模型服务 | 基于本次记录指标生成解释与回答 |

首版模型在电脑端运行。是否搬到 ESP32，留到整体闭环稳定后评估。新原型可以独立运行，不以接入雪场数据库或检索系统为前置条件。

### 8.2 建议目录（待创建）

```text
brush-mvp/

  backend/
    api/                 # 薄路由

```

原始传感器文件和个人信息默认留在本地，不写入公开仓库。若后续接入现有 PowderPilot，遵循该仓库分层、Settings、`/api/v1` 路由前缀、鉴权与 `code/msg/data` 响应契约。

### 8.3 拟定接口（尚未实现）

| 接口 | 作用 |
|---|---|
| `POST /api/v1/brush/records` | 创建记录，明确模板、验证、测试或练习用途 |
| `POST /api/v1/brush/records/{id}/stop` | 结束记录、落盘、计算质量 |
| `GET /api/v1/brush/records/{id}` | 获取元数据与状态 |

独立原型采用相同 `code/msg/data` 响应字段。数据质量失败、模板不足、设备断开、记录不存在等情况要有明确状态；接入原项目时同时落实既有鉴权和接口测试要求。具体接收设备的通道由现有链路决定，不能假设固件已支持上述接口。

### 8.4 报告契约

每份报告至少保存：

- `record_id`、`writer_id`、`mount_id`、算法/模板/预处理版本。
- 录制时长、样本数、实际保存频率、采样间隔统计、缺号与质量标记。
- `predicted_label` 或“不确定”、各类距离、拒识原因、参考模板 ID。
- 角速度模长的最大已保存值及对应时间戳/序号。
- 可用时的姿态变化范围，明确使用相对姿态及角度环绕处理方法。
- 与所选参考记录的时长差、曲线差异及各指标定义。

不输出缺乏来源的“用力不足”“墨色不匀”“结构不正”等判断。分类置信分数若未经校准，不显示成百分比概率。

## 9. 页面与 AI 体验

### 9.1 页面流程

1. **连接与校准**：设备状态、实际采样率、当前书写者/安装版本、静止标定结果。
2. **建模板**：选择字、记录示范、查看质量和已完成数量。
3. **写字**：开始/结束按钮、录制计时、三维笔杆与曲线；UI 只允许一条正在进行的字记录。
4. **结果**：候选字或“不确定”、数据质量、时长和关键事件位置。
5. **对照与回放**：选择参考，按时间或明确标注的归一化进度叠加曲线，三维笔杆同步回放。DTW 对齐显示时注明它是算法对齐，不能当作原始同时刻。
6. **AI 复盘**：围绕当前字记录、参考记录和可验证指标问答。

可以用系统字体展示识别出的字符，旁边标注“识别结果/参考字形”。三维笔杆对应真实姿态数据；系统字体字形不代表采集到了实际墨迹。

### 9.2 AI 输入与降级

AI 只读取已计算的结构化报告及引用时间片段。每条数值解释绑定 `record_id`、指标字段、时间戳和参考 ID。先用确定性程序计算，再让模型表达。

可回答：

- “这一字写了多久？与自己的示范相比快还是慢？”
- “哪一段角速度最大？带我回放。”
- “这次为什么识别为‘十’，而没有通过‘口’的匹配阈值？”
- “下一次怎样保持与这次示范相近的书写节奏？”

模型不能把匹配结果解释成已经看到了纸面字形。遇到压力、笔锋、墨色或书法等级问题，说明当前缺少对应观测。

网络或模型调用不可用时，用结构化报告、回放和标明“离线规则说明”的指标解释完成演示，不把固定文本描述为实时大模型输出。API key 只通过配置读取，不进入文档、日志或前端。

## 10. 执行顺序与分工

以下是最多约 24 小时的相对排期，不表示当前还剩 24 小时。剩余时间较少时按验收门推进；角色可由同一人兼任。

| 阶段 | 预算 | 硬件/采集 | 算法/后端 | 前端/展示 | 退出条件 |
|---|---:|---|---|---|---|
| A：完整记录 | 0～2 小时 | 安装、标定、计数器，查清保存频率 | 接收并完整落盘，检查字段 | 设备状态、计时、基础曲线 | 30 秒高频记录质量通过 |
| B：识别可行性 | 2～5 小时 | 采模板、验证及测试记录 | Baseline、DTW、阈值和评估 | 开始/结束与结果页面 | 得到独立测试报告，决定保留字数 |
| C：真实闭环 | 5～9 小时 | OLED 状态与异常提示 | API、报告、回放数据 | 三维笔杆、曲线、结果卡 | 一次新书写可识别、保存和回放 |
| D：复盘交互 | 9～12 小时 | 检查重复录制与断连恢复 | AI 证据上下文、离线说明 | 参考叠加、问答入口 | 能回答并定位本次记录事件 |
| E：实测与修复 | 12～16 小时 | 固定最终安装版本 | 独立测试、性能、误识别记录 | 修复异常状态 | 形成带条件和样本数的最终结果 |
| F：路演材料 | 16～20 小时 | 准备设备与纸笔 | 导出真实报告 | PPT、演示视频、历史回放入口 | 90 秒完整演示可重复 |
| G：缓冲 | 20～24 小时 | 设备备份与复检 | 仅修复阻塞问题 | 彩排、排版、演示环境检查 | 冻结版本与材料 |

如果只剩约 6 小时：先完成 A、B，再做一个真实识别结果页和回放；优先准备 60～90 秒演示。AI 和复杂视觉效果按剩余时间接入。识别效果未通过时，按第 7 节明确缩小范围。

## 11. 必要验证与最终验收

### 11.1 实现后需要验证的关键行为

- 数据质量：重复序号、设备重启、倒序时间、长缺口和空记录不能生成正常识别结果。
- 预处理：相同原始文件、参数与版本可复现相同结果，加载模板时验证通道和单位。
- 识别：输入中的测试标签不影响预测；模板/验证/测试记录 ID 不交叉。
- 拒识：未知动作、数据质量失败和模板缺失有独立可理解状态。
- 接口：开始、停止、重复停止、设备断开后结束、查找不存在记录等情况有一致响应。
- 保存：页面刷新、预览断开或关闭曲线不能导致后台只存“最后一帧”。
- 报告与 AI：所有数值可回到原始样本或已保存的算法结果，不混入其他人的记录。

这些验证针对核心数据与判断逻辑；文档修改本身无需新增实现测试。

### 11.2 交付检查表

- [ ] 完整记录一段约 30 秒、约 100 Hz 的六轴数据并给出质量统计。
- [ ] 固定并记录笔杆安装版本和坐标关系。
- [ ] 完成模板、验证、测试数据分离，保存采集清单。
- [ ] 实现 Baseline 与 DTW，保存参数、阈值、模板与版本。
- [ ] 完成独立测试，按实测结果确定两个或三个候选字。
- [ ] 新写一个字能保存、识别或拒识，结果不依赖目标标签。
- [ ] 三维笔杆和曲线由真实数据驱动，历史记录可以回放。
- [ ] 报告包含质量、指标来源、参考 ID 与算法版本。

## 12. 路演、PPT 与视频计划

### 12.1 约 90 秒的现场脚本

| 时间 | 演示动作 | 观众看到的证据 |
|---|---|---|
| 0～10 秒 | 展示笔与模块，说明预设识别字数 | 真实硬件、固定安装、连接状态 |
| 10～30 秒 | 开始记录，在纸上写一个字，结束 | 计时、曲线、三维笔杆、OLED 状态 |
| 30～45 秒 | 展示识别或“不确定”结果 | 候选字、数据质量、书写时长 |
| 45～65 秒 | 打开参考叠加，点击角速度事件 | 参考记录、时间点与真实回放 |
| 65～80 秒 | 问 AI“哪一段变化最大？” | 绑定本次记录的解释与跳转 |
| 80～90 秒 | 展示实测范围与下一步 | 独立样本结果，说明增加纸面视觉后的可扩展性 |

实时书写失败时显示真实状态，转用明确标注的历史记录展示已验证流程。不能把历史回放伪装成正在采集。

### 12.2 PPT 建议：6 页

1. **问题与用户**：希望记录用笔过程、对照个人示范的书法练习者；需求结论需来自实际试用或标明为假设。
2. **产品体验**：纸上写字，笔杆采集，逐字识别、回放与复盘。
3. **硬件与算法**：MPU6050、ESP32-S3、OLED、时间序列、DTW、结构化报告。
4. **真实效果**：独立测试数量、混淆矩阵、拒识、耗时；只填写最终实测数字。
5. **现场与视频**：一条实际记录从开始到问答的闭环。
6. **边界与下一步**：更多书写者和字符、重新安装适配、纸面视觉或压力采集的后续验证。

### 12.3 视频建议：45～60 秒

按“硬件近景 → 真实纸面书写 → 同步屏幕 → 识别/质量结果 → 回放 → AI 解释”拍摄。视频拍纸面仅用于路演素材，不进入本版识别算法。保留同一次记录的 ID，避免剪辑把不同记录拼成同一结果。

## 13. 开源资料与后续模型

- [OnHW 原始论文：The OnHW Dataset](https://doi.org/10.1145/3411842)：智能圆珠笔的在线英文字母识别，传感器与书写对象不同于本项目。
- [OnHW 数据集入口](https://stabilodigital.com/onhw-dataset/)：下载与使用需遵守其许可。
- [OnHW 六轴配置研究代码](https://github.com/drfatihkoksal/onhw-minimal-sensor)：包含 ResBlock1d＋BiLSTM 及六通道配置的研究；仓库明确不跟踪数据集与模型权重，不能描述为已拿到可直接识别中文毛笔字的模型。
- [tslearn 多维 DTW 文档](https://tslearn.readthedocs.io/en/stable/gen_modules/metrics/tslearn.metrics.dtw.html)：首版模板匹配的实现参考。
- 同目录原有 `README.md`：保留 MPU6050、ESP32-S3、OLED、自写六轴滤波等已有技术资料；本次产品范围与执行优先级以本计划为准。

后续只有在独立测试证明需要、且数据量足够时，再比较 1D-CNN、BiLSTM 或其他时序分类模型。训练数据首先来自同一硬件和安装条件下的真实毛笔记录；模型升级仍沿用相同的数据隔离、拒识与可追溯评估要求。
